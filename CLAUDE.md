# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

BacktestLab: backtesting of crypto trading strategies over a date range and timeframe. Monorepo with two independent apps (no root-level package manager or workspace tooling):

- `apps/web` — Next.js 16 (App Router, Turbopack) + React 19 + TypeScript + Tailwind v4 + shadcn/ui (`base-nova` style, built on `@base-ui/react`, not Radix). Owns auth (Better Auth) and the database schema (Drizzle).
- `apps/api` — FastAPI + pandas + numpy + psycopg 3. The backtesting engine. `app/services/` holds market data (Binance + CoinGecko clients, lazy quote refresh, Parquet candle reader over Cloudflare R2); `app/strategies/` holds the engine (indicators, condition registry, contradiction checks, simulation).

Both apps talk to the same **Supabase Postgres** database.

## Commands

### Web (`cd apps/web`)

```bash
npm run dev            # http://localhost:3000
npm run build
npm run lint           # eslint (flat config, eslint-config-next)
npm run typecheck      # tsc --noEmit
npm run db:generate    # SQL migrations from Drizzle schema -> apps/web/drizzle/
npm run db:migrate     # apply migrations (uses DIRECT_DATABASE_URL)
npm run db:studio
npm run auth:generate  # regenerate Better Auth tables into src/db/schema/auth.ts
npx shadcn@latest add <component>
```

### API (`cd apps/api`)

```bash
python -m venv .venv                                   # Python >= 3.12 (code uses datetime.UTC)
.venv\Scripts\python -m pip install -e . --group dev   # runtime deps + pytest/ruff (pip >= 25.1)
.venv\Scripts\fastapi dev app/main.py   # http://localhost:8000, OpenAPI docs at /docs
.venv\Scripts\ruff check . && .venv\Scripts\ruff format .
.venv\Scripts\python -m pytest          # single test: ... -m pytest tests/test_candles.py::test_name
```

Always call the venv executables explicitly (or activate the venv first). This machine also has a global Python 3.9 whose `Scripts\fastapi.exe` is on PATH: a bare `fastapi` with an empty or non-activated venv runs the app on 3.9 and fails with `ImportError: cannot import name 'UTC' from 'datetime'`. Tests live in `apps/api/tests/` (unit tests only, providers mocked with `httpx.MockTransport`; no DB or network needed).

## Architecture & conventions

- **Next.js version warning**: this is Next.js 16 with breaking changes vs. older versions (see `apps/web/AGENTS.md`). Read the relevant guide in `apps/web/node_modules/next/dist/docs/` before writing Next.js code. `next.config.ts` enables `cacheComponents` and `partialPrefetching`; typed route helpers like `LayoutProps<"/">` are global types.
- **Schema ownership**: Drizzle in `apps/web/src/db/schema/` is the single source of truth for the DB schema and migrations. Every table module must be re-exported from `src/db/schema/index.ts` (both Drizzle and the Better Auth adapter consume `* as schema`). The Python API only reads/writes via psycopg — never create or alter tables from Python.
- **Two connection strings**:
  - `DATABASE_URL` — Supabase transaction pooler (port 6543), used at runtime by both apps. Prepared statements must stay disabled (`prepare: false` in `postgres-js`, `prepare_threshold=None` in psycopg).
  - `DIRECT_DATABASE_URL` — direct connection (port 5432), only for `drizzle-kit` migrations.
  - Local secrets live in `.env.local` in each app (both apps also read `.env`; `.env.local` wins). Don't append Prisma's `?pgbouncer=true` to `DATABASE_URL`: `postgres-js` ignores it but libpq/psycopg rejects the URI. Repeated failed logins trip Supabase's pooler circuit breaker (`ECIRCUITBREAKER`, clears after ~30 s), so stop the API rather than letting the pool retry bad credentials.
- **Auth**: Better Auth server instance in `src/lib/auth.ts` (Drizzle adapter, `nextCookies` plugin), mounted at `src/app/api/auth/[...all]/route.ts`; client in `src/lib/auth-client.ts`. After changing auth config/plugins, run `npm run auth:generate` then `db:generate`.
- **Web → API**: the web app calls FastAPI through `apiFetch<T>()` in `src/lib/api.ts` (base `NEXT_PUBLIC_API_URL`). The API restricts callers via `CORS_ORIGINS`. Market data readers live in `src/lib/market.ts` (`'use cache'`): the static catalog is read directly from Postgres with Drizzle, cached for hours and prerendered (so `npm run build` needs `DATABASE_URL`, not the API); live quotes/candles come from the API with a short `cacheLife` and must be rendered inside `<Suspense>`. `drizzle.config.ts` loads `.env.local` then `.env`.
- **Market data**: the asset catalog (`assets`, `categories`) is seeded/extended through custom Drizzle SQL migrations (`drizzle-kit generate --custom`). `asset_quotes` is refreshed lazily by the API when older than its TTL. Candle history lives as Parquet files in Cloudflare R2 (`services/candle_store.py`: `candles/{PAIR}/1m/{YYYY}/{YYYY-MM}.parquet`, `15m/{YYYY}`, `1h/{YYYY}`), never in Postgres. Only 1m, 15m and 1h are stored; the other timeframes (`1m 3m 5m 15m 30m 1h 2h 4h 1d 1w 1M`) are resampled in `app/services/candles.py` from the largest stored base that divides them (`BASE_FOR`), so a 1d backtest never reads 1m data. `assets.candles_until` (exclusive) is how far R2 reaches; from there to now the last closed 1m candles come from the hot tail table `candles_recent_1m`, filled by `python -m app.sync`/warm-up through `services/recent.py` and trimmed below `candles_until`. The API never downloads candles in the read path (`get_candles` only reads R2 + Postgres; `CANDLE_LOCAL_DIR` replaces R2 in tests/dev; closed files are cached on disk, see `CANDLE_CACHE_*`). `python -m app.ingest {backfill|daily|verify} [SYMBOL]` (`app/ingest.py`) loads data.binance.vision zips (a static CDN, not banned like the REST API) into R2 and then advances `candles_until`; `.github/workflows/candles-daily.yml` runs `daily` at 03:00 UTC. Adding an asset = a custom migration row + `backfill`. `max_backtest_candles` (100 000) caps a backtest, so 1m covers at most ~69 days (mirrored in `lib/candles.ts`: `maxBacktestCandles`, `rangeFits`). `candles_1h` is deprecated: kept only so `ingest verify` can compare it with R2, drop it afterwards. A Binance 418 (IP ban) is never retried: `market_data._get` skips that host until its `Retry-After` passes (`ProviderBannedError`); only the hot tail still calls the REST API. Render's shared IP gets banned by Binance, so `python -m app.sync` (`app/sync.py`, started/stopped by hand on the owner's PC, see `docs/03-datos-de-mercado.md (Part D)`) keeps quotes and the 1m tail fresh; `PROVIDER_FETCH_ENABLED=false` makes a process never call providers (`ProviderDisabledError` → 503) and serve what is stored (R2 + tail, which then may end yesterday). All market tables have RLS enabled with no policies (blocks Supabase's Data API).
- **Accounts, guests & quotas**: Better Auth email+password (`src/lib/auth.ts`, tables in `src/db/schema/auth.ts`; pages `/login`, `/signup`). Anonymous visitors are *guests*, identified by an HMAC-signed httpOnly cookie (`bl_guest`, key `BETTER_AUTH_SECRET`) **plus** an IP bucket (`ip:<hmac>`, honours `X-Forwarded-For` only with `TRUSTED_PROXY_HOPS`), so clearing cookies/storage doesn't reset limits. Limits are rows of the `plans` table (NULL = unlimited; seeded `guest` = 2 backtests total / 1 strategy, `free` = 3 backtests per UTC day / 3 strategies / history 5; `user_plans` assigns another plan to a user; `ip_share_multiplier` scales the guest IP bucket). Enforcement is server-side only, in `src/lib/server/{identity,quota}.ts`: atomic conditional upserts on `usage_counters` / `usage_daily`; counters only count *consumption*, so deleting strategies/backtests never restores quota (only `refundBacktest` undoes a run the engine itself failed). Strategies live in the `strategies` table (route handlers `/api/strategies`, `/api/me` exposes plan+usage). `POST /api/backtests/run` is the only way to run a backtest: it consumes the quota, then proxies to FastAPI with `X-Internal-Key` (`INTERNAL_API_KEY` in both apps; the API answers 401/503 without it). Re-running an already-paid request (same digest in `backtest_runs`, e.g. reviewing history) is free; deleting it from history calls `/api/backtests/forget`. Env: `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`/`NEXT_PUBLIC_APP_URL`, `INTERNAL_API_KEY`, `API_URL` (server-side API base, defaults to `NEXT_PUBLIC_API_URL`), `TRUSTED_PROXY_HOPS` (set `1` in both apps behind one proxy).
- **Plans**: the `plans` table also holds the public catalog (`listed`, prices in US cents, `features`; seeded `pro` and `max`) and `user_plans.expires_at` limits paid access (evaluated per request in `resolveIdentity`; expired = `free`). There is **no payment provider yet**: `/plans` shows a "coming soon" notice and `components/plans/plans-grid.tsx` (the finished plan cards) is kept unused until one is integrated. A future checkout must grant plans only from a server-verified provider notification, never from a redirect.
- **Strategies & backtests**: user strategies live in the DB behind `src/lib/storage/strategies.ts` (fetches `/api/strategies`); the last N backtest summaries (N = plan `historySize`) live in the browser's localStorage behind `src/lib/storage/backtests.ts` (nothing else touches localStorage). `POST /backtests/run` is stateless: it receives the full strategy, loads warm-up candles before `from`, computes indicators in memory (never stored) and returns the result downsampled to ≤1500 display candles; reviewing a saved backtest re-runs it. The strategy model is mirrored in `apps/web/src/lib/strategy.ts` and `app/schemas/backtest.py`; a new condition kind = an entry in `conditionSpecs` (TS) + a pydantic model and a `ConditionSpec` in `app/strategies/conditions.py`, with matching contradiction rules (`findConflicts` / `find_conflicts`).
- **Preset strategies**: built-in, read-only strategies live in `apps/web/src/lib/preset-strategies.ts` (never stored in the browser). They use the regular `Strategy` shape, so they run through the same backtest path as user strategies. Engine facts they rely on (`app/strategies/engine.py`): a signal is computed at a candle's close and fills at the **next candle's open** (a signal on the last candle never fills), sells are checked before buys, one order per candle, a 100 % buy leaves no cash, a partial sell on a *state* condition repeats every candle but a partial sell leaving less than `DUST_PCT` (1 %) of the initial capital sells everything, and equity is the **liquidation value** (an open position counts as sold at the close, exit fee included). The win rate counts closed round trips (flat → flat), not sell orders.
- **Visual strategy builder**: `components/strategy/strategy-form.tsx` edits a node graph (`lib/strategy-graph.ts`, pure and tested in `tests/strategy-graph.test.ts`), not `Rule[]` directly. Only three node types: the price (column 0), conditions and buy/sell actions (the order amount lives in the action node). A wire means "both must hold": every action node is one rule (`graphToRules`) made of all the conditions that lead to it, recursively and de-duplicated (max 3, `canConnect`/`setMode` refuse what would exceed it); a condition can have several wires in and out (to conditions or actions). A node with 2+ wires in shows an AND/OR switch (`mode`, default AND): an OR is expanded into alternatives and each alternative is saved as its own plain-AND rule (first keeps the action id, the rest `<id>~<n>`). Wires always go to a column further right (`moveNode` drops the ones a move turns backwards); conditions and actions sit freely in any column but the first, and the panel shows the used columns plus a free one (`shownColumns`, `builder/builder-layout.ts`; wires are computed from it, no DOM measuring). Only first-column conditions auto-wire to the price. `rulesToGraph` lays saved rules out again as chains, so the stored model, the API and the presets are unchanged and node positions are never saved. Node colours by type live in `nodeStyles` (`builder-node.tsx`). Drag logic (pointer events, no dnd library) lives in `builder/strategy-builder.tsx`; `PresetDetail` shows the same canvas with `readOnly` (rules from row 0). Incomplete nodes block saving (`graphProblems` in the form). The unsaved draft lives in `sessionStorage` (`bl_strategy_draft2:<id|new>`, old-format drafts are ignored) so it survives the ES/EN switch (a full page load); leaving with changes asks first (in-app links open a pop-up, tab close/reload gets the browser prompt).
- **Condition options**: every condition carries optional shared settings, `trend` (`up`/`down`: close above/below its EMA of `trendPeriod`, default 50; absent = either) and `lasts` (the signal stays active N candles, default 1), mirrored in `lib/strategy.ts` (`ConditionOptions`, folded into `specOf`) and `app/schemas/backtest.py` (`ConditionOptions`) / `app/strategies/conditions.py` (`_with_options`). They are part of the condition's subject, so differently configured conditions are never compared as contradictory, and they don't apply to "price since the buy". Edited in the "Advanced settings" block of `condition-fields.tsx`.
- **Candlestick patterns**: the `candle-pattern` condition kind is detected in `app/strategies/patterns.py` (boolean Series that is True on the *last* candle of the pattern, so there is no look-ahead; simplified trend-context/gap/tolerance definitions are documented at the top of the module) and mirrored in `apps/web/src/lib/candle-patterns.ts` + `components/strategy/candle-pattern-picker.tsx`. Add a pattern in both places, with tests in `tests/test_patterns.py`.
- **Languages (es/en) & SEO**: every page lives under `app/[lang]/` (root layout there; `lang` read with `next/root-params` via `getI18n()` in `lib/i18n-server.ts`, `useI18n()` from `components/i18n/locale-provider.tsx` in client code). Spanish keeps the unprefixed URLs, English is `/en/...`: `src/proxy.ts` rewrites unprefixed paths to `/es/...`, 308s `/es/...` back, and honours the `bl_locale` cookie set by `LanguageSwitcher`. Texts are inline pairs `t("es", "en")`; shared libs (`strategy.ts`, `format.ts`, `candle-patterns.ts`, `preset-strategies.ts`) take a `locale` argument (Spanish by default, which the server validation uses). Links must go through `href(path)` / `localizePath`. Each page exports `generateMetadata` built with `pageMetadata()` (`lib/seo.ts`: canonical, hreflang, Open Graph, `noindex` for private pages); `app/robots.ts`, `app/sitemap.ts`, `opengraph-image.tsx` files, `[lang]/not-found.tsx` (for `notFound()`) and `app/global-not-found.tsx` (unmatched URLs, `experimental.globalNotFound`). `npm run build` also needs the API reachable (it prerenders pages that read live data).
- **Legal pages**: `/privacy`, `/terms`, `/cookies`, `/legal` (indexable) are bilingual inline texts laid out by `components/legal/legal-page.tsx` (sections as `{heading, body}`; update date `siteConfig.legalUpdated`). Links come from `siteConfig.legal` (footer row and sign-up checkbox in `auth-form.tsx`); the provider's data is `siteConfig.operator` (placeholders until filled in). They are drafts for a lawyer's review. The cookie table in `/cookies` and the processors list in `/privacy` must be updated whenever a cookie, storage key, analytics or a new provider is added (analytics would require a consent banner). Payments (Phase 5) will add on-chain data to `/privacy` and the payments/refunds section of `/terms`.
- **Display currency (USD/EUR)**: market figures (prices, 24h range, volume, market cap, price chart) are stored in USD and shown in the visitor's currency, chosen with `CurrencySwitcher` (header + mobile menu) and remembered in the `bl_currency` cookie, which is read on the client only (`CurrencyProvider`, `useSyncExternalStore`, USD on the server render) so pages stay prerendered. The EUR rate comes from Frankfurter (`lib/fx.ts`, `'use cache'` hours); if it fails, only USD is offered. Show USD amounts with `<Money value compact? />` (Server Components) or `useMoney()` (client). Backtests (capital, PnL, replay) stay in USDT, the engine's currency; never convert those.
- **Landing (`/`)**: marketing page built from `components/landing/` (one Server Component per section, animations as client islands in `components/landing/art/`, shared hooks in `motion.ts`: they play only on screen, pause off screen and show their final frame with reduced motion). The animations use **real** backtest results from `src/lib/landing/snapshot.json`, written by `python -m app.landing_snapshot` (`apps/api/app/landing_snapshot.py`, runs the presets through the engine on BTC; re-run by hand to refresh, the preset rules there mirror `preset-strategies.ts`). Pure geometry in `lib/chart-geometry.ts` (shared with the backtest replay, tested in `tests/landing-geometry.test.ts`); the motion hooks live in `lib/motion.ts`. CSS-driven animations use the `lp-*` keyframes in `globals.css`, whose elements' own styles are the final frame.
- **Pages & backtest UI**: `/` landing, `/assets` asset catalog, `/assets/[symbol]` (config + price chart + that asset's backtest history via `AssetBacktests`), `/strategies` (+ `new`, `[id]`), `/backtests` (history of the last runs). Running a backtest opens the replay dialog (`ReplayPlayer` in `components/backtest/backtest-replay.tsx`, full window by default via `REPLAY_DIALOG_CLASS`; `ExpandButton` shrinks it); history rows (`BacktestList`) re-run the saved strategy snapshot in the same dialog (passing `recordId`). The replay is all SVG: `replay/` holds the playback clock (`use-playback.ts`: position in candles, 1×/2×/4×, seek, pause in hidden tabs; every frame is a pure function of the position), the price chart (`price-chart.tsx`, only visible candles drawn, line mode when dense, drag/wheel zoom once finished), equity vs buy and hold and drawdown panels (`series-charts.tsx`) and the live KPIs/timeline (`live-panels.tsx`); keyboard: space, ←/→ (Shift: trade), 1/2/4, End/S, R. When it ends the same dialog turns into the report (`report/`: verdict with seal, reliability notes and previous-run comparison, key figures, 4 charts, trade table whose rows have a "mark on chart" button and a "buys and sells" button that opens `TradeDetailDialog`, folded advanced ratios, PDF/PNG/CSV export). At the end the live tiles that repeat a key figure fly to their card ("dock", `replay/dock.tsx`, timings in `SETTLE`); it is a pure function of `dockU` like the rest of the cabin. On wide screens (`useMediaQuery` ≥ 1024 px) the column that held the tiles then takes the verdict (`VerdictPanel side`, warnings included; the previous-run comparison goes in a strip under the charts, `VerdictNotes only="previous"`); on narrow ones the column folds away and the verdict stays on top. A folded "Strategy rules" section (`report/rules-panel.tsx`, the read-only `StrategyCanvas` of `run.strategy.rules`) sits after the trades table; PDF/PNG exports unfold it (`data-collapsible` rules in `globals.css`). All report figures come from the engine at full resolution (`app/strategies/analytics.py` → `metrics`, `roundTrips`, `periods`, `benchmark`, `drawdown` in the result); the pure logic on top (live figures, verdict rules, warnings, previous run, CSV) is `lib/backtest-report.ts`, tested in `tests/backtest-report.test.ts` against a real engine result (`tests/fixtures/backtest-result.json`). Report animations use the `bt-*` classes in `globals.css` (`.bt-armed` until in view, final frame for reduced motion, print and `.bt-exporting`). History records are `schemaVersion: 2` (v1 = previous engine: still listed, never compared). Any list of runs must go through `useRecentBacktests()` from `lib/storage/backtests.ts`, never read localStorage directly.
- **Warm-up & keep-alive**: `GET /health` (public, exempt from rate limits) schedules `services/warmup.py` after responding: refresh quotes and extend the stored candles of assets that already have some, throttled in-process (`WARMUP_MIN_INTERVAL_SECONDS`, 300) and never raising. `ensure_fresh_quotes` is stale-while-revalidate: a snapshot older than the TTL but younger than `QUOTE_MAX_STALE_SECONDS` (900) is served as is while one background thread refreshes it; older/missing snapshots block as before. an external monitor (cron-job.org, Europe/Madrid time zone, no code here; see `DEPLOY.md` Paso 7) pings it every 12 min between 12:00 and 01:00 to keep the free Render instance awake (`render.yaml` is `plan: free`). Don't raise `cacheLife` `expire` in `lib/market.ts` to ≥5 min: it would move live data into the prerender.
- **API structure**: routers in `app/api/routes/` are registered in `app/main.py`. Settings come from `app/core/config.py` (`pydantic-settings`, reads `.env` then `.env.local`, accessed via cached `get_settings()`). DB access uses a **sync** `psycopg_pool.ConnectionPool` opened/closed in the FastAPI lifespan; endpoints get a connection via `Depends(get_conn)`. Endpoints doing DB or pandas work should be plain `def` (run in the threadpool), not `async def` — deliberate choice for CPU-bound work and psycopg async issues on Windows.
- **Route handler hardening** (see `SECURITY.md`): every `app/api/**/route.ts` exports a low `maxDuration` and calls `enforce()` from `lib/server/rate-limit.ts` (per-IP + global before `resolveIdentity`, per-subject after it for writes), returning `tooManyRequests()`. JSON bodies go through `readJson` (size + depth caps). `UPSTASH_REDIS_REST_URL`/`_TOKEN` (optional) share the limits across instances. The DB grants nothing to Supabase's `anon`/`authenticated` roles (migration `0008`); new tables need no policies.
- Path alias `@/*` → `apps/web/src/*`. `cn` util is re-exported from the `cn` package in `src/lib/utils.ts`.
- Environment templates: `apps/web/.env.example`, `apps/api/.env.example`.
